# STILL product brief

## Promise

**People finish the task, even when the interface breaks.**

STILL is a continuity and repair system for supported digital-service journeys. It protects the immediate user outcome first, then turns a verified failure into bounded engineering work with evidence-backed release decisions.

## First user outcome

A keyboard user can reserve a synthetic university advice appointment through `/book`. If the primary slot interaction is intentionally broken in an isolated demo mode, `/simple` remains usable and writes the same booking through the same Rust service.

## Operator outcome

An operator can see what happened today, which journey is healthy, which incidents are actionable, what repair state exists, and which evidence supports a release decision. The UI only reports stored state returned by the API.

## Explicit non-goals

- No arbitrary website repair.
- No real university, NHS, government, student, payment, or personal data.
- No claim of universal offline completion when the authoritative backend is unavailable.
- No autonomous merge or deployment without an explicit policy and real GitLab permissions.
- No fabricated agent activity, metrics, or customer traction.
